5. 两个摄像头不能选同一个；确认后选择会自动保存到 config.json（原子写入，
   中断也不会写坏文件），其他设置不受影响

找不到两个可用摄像头时会提示，插好两个 USB 摄像头后按 R 重扫即可。
不想每次都选：把 config.json 里 camera.selection.startup_pick 改为 false，
或设置环境变量 STEREO_POSE_NO_CAMERA_PICK=1。

重要提醒（标定与摄像头的对应关系）：
- 以前保存的标定只对"同一对物理摄像头 + 同一安装几何"有效。
  换电脑后摄像头编号可能变化（例如原来的 0/1 变成 1/2）。
- 如果启动时检测到当前左右编号与标定记录的编号不一致，程序会打印醒目的
  警告横幅：请人工确认物理左右摄像头是否和标定时相同；
  只要摄像头和支架没动，旧标定通常可以继续用；
  换过设备或挪过支架，请重新标定（按 C 采集 + R 求解）。
- 程序永远不会因为编号变化自动删除或覆盖已有标定文件。

Task002B 新增说明（S 快照 + M 开发者面板）：
- S 键：把"当前这一帧"的左右原始画面 + 已完成的姿态识别结果一次性存成
  一个自包含的诊断文件夹（runtime/diagnostics/snapshots/时间戳/），包含：
  * left_raw.png / right_raw.png       左右原始画面（未标注、未缩放）
  * left_annotated.png / right_annotated.png   带关键点名字 + 置信度的标注图
  * manifest.json    版本化清单：每个关键点的原始观测坐标/置信度都会原样
    保留（包括置信度为 0 的"未检出"占位），可用性用独立字段区分
    （missing/missing_reason 说明为什么不可用，low_confidence 表示检出但
    低于接受阈值）
  * calibration_snapshot.npz    复算所需的标定矩阵（无激活标定时不存在）
  * README.txt          文件说明
- 按 S 不会重新抓帧、不会重新跑 YOLO 推理，保存的正是当前跟踪循环里
  已经拿到的那一对画面和姿态结果，所以不影响实时性。
- 保存过程先写入 .partial 临时目录、全部成功后才改名成正式文件夹；
  如果保存失败不会留下"看似完整的半成品"，也绝不影响历史快照。
- 离线复算（不需要摄像头和模型，只要 NumPy + OpenCV）：
  python tools/inspect_snapshot.py <快照目录>
  会重算矫正坐标和极线误差并与 manifest 里存的值交叉核对：
  退出码 0 = 全部一致；1 = 无法复算（清单/标定缺失或损坏）；
  2 = 复算完成但发现与存储值不一致。
- M 键：收起时画面只显示左右摄像头编号、标定状态、接受关节数、
  实测帧率和警告，保持画面干净；按 M 展开后额外显示设备、拒绝计数、
  Stereo RMS / 极线 / 重投影误差、host grab skew、One Euro 参数、
  采集耗时（grab=NNms）和完整热键行。重要警告在收起和展开两种状态下
  都始终显示在最前面，展开面板不会挡住警告。
- 画面上的 fps 是"全流程实测帧率"（抓帧 + 推理 + 三角化 + 发布 + 渲染），
  不是相机采集周期；采集耗时单独显示为 grab=NNms，两者不会混淆。
- 快照文件夹含人像画面，绝不要提交到 Git 或上传到任何外部服务。

Task002 新增说明：
- D 键：逐关节输出每个被拒绝关节的精确原因（置信度/极线/重投影/深度/质量/速度），
  用于解释偶尔消失的肩/肘等关节点为什么没被接受。
- V 键：用同一块 25mm 棋盘做 3D 度量验证，输出横向/纵向间距、尺度误差、
  平面拟合残差、极线/重投影误差、深度范围，并保存 JSON 报告到
  runtime/validation/metric_YYYYMMDD_HHMMSS.json（不会被标定历史清理删除）。
- 度量验证为单帧（sample_mode=single_frame），报告内明确标注。当前不设通过/失败阈值，
  只暴露测量值。
