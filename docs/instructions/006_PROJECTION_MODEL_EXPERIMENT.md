# 双目投影模型与边缘精度对照

对应 [Issue #9](https://github.com/CaiKerman/stereo-pose/issues/9)。开发基线为 [PR #8](https://github.com/CaiKerman/stereo-pose/pull/8) 的 `d7bf68fcf5889bec660234abb43369701b510a30`。本实验适用于不同焦距、不同内参和存在夹角的双目相机。

## Windows 实测步骤

1. 在已有项目目录中更新代码，保留本地 Python 环境、模型、`config.json` 和 `runtime`。运行 `RUN_ME`，确认左右物理相机和安装位置。
2. 在「高级工具 → 记录相机输出设置 B」里分别填写两台相机的设备标识、Webcam FOV、EIS、固件和成像模式。OpenCV 能读取的分辨率、FPS、后端及编码会单独记录。相机菜单中确认不了的字段可以留空。Action 4 的标称镜头 FOV 不能代表 USB 实际输出。
3. 进入「双目标定 C」。如需验证动态裁切或映射漂移，先固定棋盘和相机，静止后在「高级工具」按 J。保持装置不动，在一段使用时间或指定设置变化前后再按 J，对照左右角点位移 P50/P95 和分辨率。变化也可能来自物理移动，需同时核查固定方式。
4. 一次采集覆盖中心、中间、边缘和四角，兼顾不同距离和倾斜角度。默认至少 12 对可信样本。建议采集多于 12 对，留出独立棋盘姿态。24 对仍是覆盖目标。首次求解、或有足够样本时返回/退出，会封存同一次拍摄的图像和亚像素角点。封存后仍可反复求解。重启后可在「高级工具 → 打开已有棋盘数据 O」选择 `observations.npz`。
5. 下拉选择「普通针孔」「扩展针孔」「鱼眼」，逐一点击「计算所选方案 R」。在「详细诊断」查看留出误差和报告路径。切换「预览 → 矫正预览」后，比较「裁切取满」和「保留视野」。取景下拉只改变画面。程序仍在原始像素上采样。
6. 选择一个已完成的模型，点击「启用所选标定 A」并确认。先检查预览及告警，再用 W 重新建立工程坐标。W 初始显示完整原始冻结图。H 可切换矫正预览。切换预览时，图码识别及坐标拟合始终使用同一批原始像素。
7. 在同一套相机设置下，比较与 W 拟合控制点分开的已知 XYZ 参考点。对每个中心和边缘位置重复测量，保留不通过质量门槛的点。V 仍可做已知棋盘尺寸的几何检查。人体识别误差需另测。

兼容模式保留 C → R 求解并启用普通针孔。其他模型可用下面的离线命令求解，再用桌面 L 加载，或设置明确的 NPZ 路径。旧 NPZ 继续按原有普通针孔语义读取。已知设备输出模式或分辨率失配时，仍可查看/导出文件和预览原图，可信 XYZ 与 CSV 会暂停。

## 离线命令

以下命令可在 Windows 项目目录中用原有 Python 解释器单行执行。按实际情况替换路径。

```powershell
python tools/calibration_experiment.py --config config.json fit "runtime/sessions/实际会话/observations.npz" --model all
```

```powershell
python tools/calibration_experiment.py --config config.json audit "普通针孔.npz" "扩展针孔.npz" "鱼眼.npz" --references "references.json"
```

历史 NPZ 缺少 `image_size` 时，使用 `--image-size WIDTH HEIGHT` 指定已核实的原始尺寸。省略 `--references` 时，仅输出投影映射、可逆性和取景审计。参考 JSON 示例中的值是合成示意，`uv_left` 和 `uv_right` 必须替换成实际原始像素。相同 `id` 表示同一固定点的重复观测。

```json
{
  "unit": "mm",
  "frame": "camera_left",
  "points": [
    {"id":"edge-1","xyz_mm":[100,40,1100],"uv_left":[690,410],"uv_right":[465,409]}
  ]
}
```

使用工程坐标时写 `"frame": "world"` 和 `"world_name": "实际坐标名称"`，每个模型均须使用自身有效的 W NPZ，且坐标系由同一工程基准定义。使用 `camera_left` 时输入相对于物理左相机的独立真值。程序用各模型的 R1 逆变换将测量值转换回该共同坐标系。JSON 报告记录每轴有符号偏差、重复观测标准差、误差长度 P50/P95 和拒绝数。少量重复观测时，统计量仅供初步排查。

## 读报告

- 每次求解保存独立 NPZ、JSON 报告和映射 PNG。JSON 记录原始数据集 SHA-256、模型、OpenCV 和算法版本、左右设备记录、候选 NPZ SHA-256、几何指纹及失败原因。数据及图像保存在本机。已封存会话和候选标定不会被滚动清理。
- 同一数据集固定留出整幅棋盘姿态。三个模型的对照拟合使用同一批训练姿态和留出姿态。最终可启用的 NPZ 使用完整可信样本，并可按原有规则去除坏帧。共有样本的角点顺序在模型拟合前确定。广角初拟合只用于检查左右对应。样本不足或留出拟合失败时会明确标记。
- 分区以原始图像坐标划分，左右分别统计中心、中间环带、边缘、四角。覆盖率以 12×8 网格占据情况计。区域报告包含单目原始像素重投影、双目极线残差、通过逆投影和静态质量检查的比例。留出单目重投影会用该张图的角点估计棋盘姿态，内参及双目外参保持冻结。
- 映射报告给出 33×25 原始像素网格、失败点位、正反投影残差、径向中央单调域、有效射线角度、输出覆盖和投影矩阵。普通/扩展模型用 alpha，鱼眼用 balance，fov_scale 为 1。鱼眼覆盖率用实际采样估计，OpenCV 的鱼眼接口无普通模型的矩形 ROI。
- 对照 alpha/balance 时，虚拟焦距变化会缩放像素残差。优先比较报告里的极线平面角差（mrad）及独立真值 XYZ。正式测量用固定 P1/P2。扩展和鱼眼测量投影使用不低于较大原始焦距的虚拟焦距，防止视野极宽时把相同角度误差压成很小的像素值。原有像素质量阈值仍由配置决定。
- 已证明的结论限于合成场景和计算路径。实机有可复算的留出结果、稳定的固定图案、独立 XYZ 后，才可判断三种疑点的相对贡献。若不同模型在匹配设置下均有稳定的边缘偏差，再以等覆盖范围、独立 XYZ 和相同评价定义对照长焦方案。旧标定相同文件名不能证明相机几何或输出稳定。
